# mediahost

Система показа видеороликов на смарт-телевизорах (ТВ-плеер + административный раздел).

## Быстрый старт (Ubuntu 24.04, PHP 8+)

```bash
apt install php-cli ffmpeg            # ffmpeg нужен для конвертации
cp src/config.php.example src/config.php   # при необходимости поправить пути/таймзону
php src/auth.php add <логин> "<пароль>"    # создать пользователя админки (мин. 8 символов)
```

Вход в админку: `/admin/` — логин `admin`, пароль задаётся командой выше (в репозитории паролей нет, хранится только argon2id-хэш в `data/users.json`).

Cron для очереди конвертации:
```cron
* * * * * www-data /usr/bin/php /var/www/mediahost/bin/worker.php >> /var/log/mediahost-worker.log 2>&1
```

## Структура
- `index.html`, `playlist.php` — ТВ-плеер (формат ответа совместим со старым, не менять без тестов на Chrome 22)
- `admin/` — административный раздел (SPA + JSON API в `admin/api/`)
- `src/` — ядро: `engine.php` (плейлист), `ffmpeg.php` (конвертация), `auth.php`, `util.php` (JSON-хранилище, логи), `config.php` (не в git)
- `bin/worker.php` — воркер очереди перекодирования (миграция v1→v2 выполнена, скрипт удалён)
- `data/` — «база данных» в JSON: `videos.json` (ролики + их расписание), `specials.json` (особые дни), `users.json`, журнал `logs/admin-*.log`, состояние ротации `state/`
- `media/` — готовые ролики; `uploads/` — исходники до конвертации; `cache/` — кэш

## Модель данных (v2)
Расписание хранится **на ролике**: каждый ролик имеет тип (`main` — основной, показывается строго по порядку; `additional` — дополнительный, выбирается случайно из активных) и список периодов активности `schedule:[{id,start,end}]`. Один ролик может быть расписан многократно в разные даты.

`specials.json`:
- `tech_periods` — периоды технического закрытия (наивысший приоритет: видео/картинка-заставка);
- `sanitary_dates` — произвольные санитарные даты;
- `weekday_periods` + `weekday_sanitary` — периоды действия и день недели санитарных дней.

Приоритеты движка: техзакрытие → санитарный день → ротация активных роликов. Если активных роликов нет — плейлист пустой, админ показывает предупреждение «ПУСТО».

## Ролевая модель и управление пользователями

В системе действуют две роли:
- **Администратор (`admin`)** — управляет учётными записями в разделе «Пользователи», настраивает параметры конвертера (`ffmpeg`) в разделе «Настройки», просматривает «Плейлист сейчас» и «Журнал». Доступ к вкладкам «Ролики и расписание» и «Особые дни» у администратора закрыт.
- **Редактор (`editor`)** — управляет библиотекой роликов, расписанием показов и особыми днями, просматривает текущий плейлист и журнал действий.

Смена собственного пароля доступна всем из шапки админки; администратор может менять пароль любого пользователя без подтверждения текущим.

CLI:
```bash
php src/auth.php add admin 'StrongPass123'      # добавить (по умолчанию роль admin)
php src/auth.php add editor 'EditorPass123'     # добавить редактора
php -r '$u=json_decode(file_get_contents("data/users.json"),true); foreach($u as &$x){if($x["login"]==="admin")$x["passhash"]=password_hash("NewPass123",PASSWORD_ARGON2ID);} file_put_contents("data/users.json",json_encode($u,JSON_PRETTY_PRINT));'  # сбросить пароль
```

## Инструкция для администратора

1. **Вход и общие элементы шапки:** откройте `/admin/`, введите логин и пароль (`Enter` или «Войти»). В верхней панели доступны переключение темы оформления (светлая/тёмная), смена собственного пароля («Пароль») и выход из системы («Выход»).
2. **Плейлист сейчас:** на вкладке отображается текущий режим эфира (обычная ротация, «САНИТАРНЫЙ ДЕНЬ» или «ТЕХНИЧЕСКОЕ ЗАКРЫТИЕ»), активные ролики и симулятор последовательности показов на выбранные дату, время и число слотов.
3. **Настройки конвертера (`ffmpeg`):** задайте разрешение (`-s`), видеокодек (`-c:v`), формат пикселей (`-pix_fmt`), профиль (`-profile:v`), уровень (`-level:v`), пресет скорости (`-preset`), `CRF` или битрейты (`-b:v`, `maxrate`, `bufsize`), аудиопараметры (`-c:a`, `-b:a`) и длительность ролика из изображения по умолчанию, проверьте команды предпросмотра и нажмите **«Сохранить настройки»**.
4. **Пользователи:**
   - Создание учётной записи: укажите логин (латиница), пароль (от 8 символов) и роль («Редактор» или «Администратор»), затем нажмите **«Создать»**.
   - Изменение роли: выберите новую роль в выпадающем списке строки пользователя и нажмите **«Сохранить роль»**.
   - Сброс/смена пароля: нажмите **«Пароль…»** в строке пользователя, введите новый пароль и подтвердите смену.
   - Удаление пользователя: нажмите **«✕»** и подтвердите действие (нельзя удалить самого себя и оставить систему без администраторов).
5. **Журнал:** просматривайте хронологию действий пользователей (от новых к старым) с указанием времени, логина, IP-адреса, события и деталей; используйте **«Обновить»** для получения свежих записей.

## Инструкция для редактора

1. **Вход в систему:** откройте `/admin/` и войдите под учётной записью редактора. В навигации доступны разделы «Плейлист сейчас», «Ролики и расписание», «Особые дни» и «Журнал».
2. **Плейлист сейчас:** проверяйте текущий эфир, активные основные и дополнительные ролики, ближайший файл и `watchdog`, а также моделируйте расписание на нужную дату и время (до 50 показов).
3. **Ролики и расписание:**
   - **Загрузка:** перетащите или выберите видеофайл либо изображение в области загрузки (появится локальный предпросмотр), укажите название (из него транслитерацией формируется имя файла) и тип («Основной» или «Дополнительный»). Для изображения задайте длительность в секундах (по умолчанию 60 с) и нажмите **«Загрузить и конвертировать»**.
   - **Статус и предпросмотр:** дождитесь статуса `ready` (статусы очереди и конвертации обновляются автоматически). Нажмите на превью или кнопку **«▶»**, чтобы просмотреть готовый `mp4`-ролик.
   - **Порядок основных роликов:** меняйте порядок перетаскиванием ячейки номера за `⠿`, кнопками **«▲»** / **«▼»** или нажмите **«Перенумеровать»** для сохранения текущей последовательности.
   - **Редактирование и удаление:** после изменения названия или типа нажмите **«Сохранить»** (при наличии несохранённых правок отображается индикатор `●`). Кнопка **«✕»** удаляет ролик и файл.
   - **Периоды показа:** нажмите **«＋ Периоды»** / **«Изменить периоды»**, задайте интервал «с» и «по» и нажмите **«+ Добавить период»** (существующие интервалы можно править кнопкой **«✓»** или удалять кнопкой **«✕»**).
4. **Особые дни:**
   - **Санитарные дни по дню недели:** выберите день недели, отметьте «включено» и нажмите **«Сохранить»**; при необходимости загрузите/замените заставку санитарного дня и добавьте периоды действия («с» и «по»).
   - **Периоды технического закрытия:** укажите даты «с» и «по», выберите заставку (или загрузите новую прямо к периоду кнопкой **«⬆»**) и добавьте/сохраните период (техзакрытие имеет приоритет над санитарными днями по дню недели).
5. **Журнал:** контролируйте историю событий в системе и обновляйте список по кнопке **«Обновить»**.

## Конвертация (серверные аналоги windows-скриптов)
- Видео: `ffmpeg -i in -s 1280x720 -c:v libx264 -pix_fmt yuv420p -profile:v baseline -level 1.3 ... out.mp4`
- Изображение → видео: то же + `-loop 1 -t <сек>` (по умолчанию 60).
Пресеты настраиваются в `src/config.php` и в разделе «Настройки» административного интерфейса.

## Лимиты загрузки больших видеофайлов

По умолчанию в PHP стоят `upload_max_filesize=2M` и `post_max_size=8M`. При загрузке видео большего размера PHP полностью игнорирует тело запроса (`$_FILES` пуст), и админка показывает ошибку «Файл не загружен». Для загрузки роликов до 2 ГБ нужно поднять лимиты.

### Apache + php-fpm (Ubuntu 24.04)
Создайте файл `/etc/php/8.3/fpm/pool.d/tvplayer-uploads.conf`-подобную настройку — лучше всего прямо в пуле сайта, например в `/etc/php/8.3/fpm/pool.d/www.conf` добавить:

```ini
php_admin_value[upload_max_filesize] = 2G
php_admin_value[post_max_size] = 2100M
php_admin_value[max_execution_time] = 0
php_admin_value[memory_limit] = 512M
```

Перезапустите: `sudo systemctl restart php8.3-fpm`.

В конфиге Apache для location `/admin/api/` увеличьте ограничение тела запроса:

```apache
LimitRequestFieldSize 65536
# mod_fcgid / mod_proxy_fcgi обычно не режут тело; mod_security может — проверьте SecRequestBodyLimit
```

### Apache + mod_php
В каталоге `admin/api/` уже лежит `.htaccess` с нужными `php_value` (работает только при mod_php и AllowOverride).

### Встроенный php -S (тестовая среда разработки)
Лимиты задаются через `-d`:

```bash
php -S 0.0.0.0:8080 -d upload_max_filesize=2G -d post_max_size=2100M -d memory_limit=512M
```

### Nginx + php-fpm
В `server`/`location ~ \.php$`:

```nginx
client_max_body_size 2100m;
fastcgi_read_timeout 3600;
```

и те же `php_admin_value` в пуле php-fpm, что выше. После изменений перезапустите nginx и php-fpm и повторите загрузку. Значение `max_upload_size` в настройках приложения (страница «Настройки») должно быть не больше серверных лимитов.
